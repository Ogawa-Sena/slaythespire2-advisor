# 画面の読み取りの検証結果（CLAUDE.md「最初にやること 1」）

- 検証日：2026-11-11
- 使った画像：`samples/` の9枚（マップ、商人の入口、ショップ、カード報酬）と、`samples/screens/` のカード一覧54枚

## 1. 試した読み取り方法

| 方法 | 速さ | 準備 |
|---|---|---|
| **Windows 標準のOCR**（Windows.Media.Ocr、日本語） | **1画面まるごとで 0.06〜0.1秒**、名前の帯1つなら約0.007秒 | 不要（Windows に最初から入っている） |
| **AI の画像読み取り**（`claude -p`） | 1回ずつ起動すると **7.5〜15秒**。**起動したままにすると 約3秒** | Claude Code の CLI（2026-11-12 に winget で導入・ログイン済み） |

## 2. Windows 標準のOCRの結果

### 画面まるごとを読んだ場合
| 読みたいもの | 結果 |
|---|---|
| カード報酬画面の「カードを選択」「スキップ」 | ○ 正しく読めた → **画面の種類の判定（F-02）の手がかりに使える** |
| 効果テキスト（例：「カードを1枚引く。」「ナイフが追加で4ダメージ」） | ○ おおむね読める。ただし「ブロック」→「プロック」のような小さな誤りがある |
| 価格（例：`◎77`、`◎168`）・所持ゴールド（`◎110`） | ○ 読める（コインの絵が「◎」になる） |
| **カード名**（飾り付きの帯の上の文字） | **× ほとんど読めない**（カード報酬の3枚のうち「剣の舞」だけ） |

### カード名の帯だけを切り出し、3倍に拡大した場合
- カード報酬画面：3枚中 **2枚は正確**、1枚は「精度上塾-」（正しくは「精度上昇」）
- カード一覧の名前の帯 430個を読んだ結果：

| 結果 | 件数 | 割合 |
|---|---|---|
| 公式のカード名と完全に一致 | 169 | 39% |
| 少し違うが、似た名前を探せば当てられる | 102 | 24% |
| 読めたが当てられない | 69 | 16% |
| 何も読めなかった | 90 | 21% |

→ **カード名だけで当てられるのは6割ほど。名前だけでは足りない**

## 3. AI の画像読み取りの結果
- カード報酬画面の名前の帯（文字の部分だけを切り出した画像）を読ませたところ、**どの方法でも毎回3枚とも正確**（脱出計画・精度上昇・剣の舞）
- AI に送る画像は、**文字の部分だけを切り出す**（カードの絵は送らない）。
  送る量が減って速くなり、カードの絵に AI の判断が引っぱられることもなくなる

### 速さ（2026-11-12 計測。各3回）
| 呼び出し方 | 1回あたり |
|---|---|
| 標準のモデル、`claude -p` を毎回起動、画像はファイルを読ませる | 13.1〜14.6秒 |
| 軽いモデル（haiku）、毎回起動、画像はファイルを読ませる | 7.5〜8.2秒 |
| 軽いモデル、毎回起動、画像を直接渡す | 7.6〜8.7秒（AIの処理は約2.6秒、残りは起動の時間） |
| **軽いモデル、`claude -p` を起動したままにして、画像を直接渡し続ける** | **2.8〜3.2秒**（最初の1回だけ4.1秒） |

- 時間の大半は **CLI の起動（約5秒）**。ツールの起動時に `claude -p` を1回だけ起動しておき、
  画面を読むたびに画像を送る方式なら **5秒以内に収まる**
- 注意：`claude -p` に入力を渡さないまま起動すると、入力を待って **3秒** 余計にかかる（入力を空にして起動すればよい）
- 注意：起動したままだと、送った画像が会話の履歴にたまっていく。ランが終わるたび、または一定回数ごとに起動し直す必要がある
- 使ったオプション：`--input-format stream-json --output-format stream-json --verbose --model haiku --tools "" --no-session-persistence --strict-mcp-config --disable-slash-commands`

## 4. 画面の種類の判定（F-02）の手がかり

| 画面 | 手がかり |
|---|---|
| カード報酬 | 上に「カードを選択」、下に「スキップ」の文字。カードの位置も決まっている |
| ショップ | 価格（`◎数字`）がたくさん並ぶ。「カード削除」のような専用の文字は今回の画像では見つからなかった |
| 商人の入口（ショップを開く前） | 「次へ」の文字だけ。ショップとは別の画面として扱う |
| マップ | 「凡例」「不明」「商人」「宝箱」などの文字 |

- 補助案：セーブファイルのマスの記録から「今いるマスがショップか」を確かめられる可能性がある（要調査）

## 5. おすすめの組み合わせ（案）

1. **画面の種類**は Windows OCR で画面全体を読み、手がかりの文字で判定する（0.1秒）
2. **カードの特定**は、名前だけでなく、**名前・効果テキスト・コストを合わせて**、DB のカードと照合する
   - 効果テキストは Windows OCR でよく読めるので、名前の読み間違いを補える
3. それでも自信が低いカードだけ、**AI の画像読み取り**に回す（文字の部分だけを切り出して送る）
4. 統計による順位は、OCR の結果ですぐに表示する（5秒以内の条件を守るため）
