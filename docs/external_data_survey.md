## おすすめ：Spire Codex をメインにする

理由：
1. **規約で公開APIの利用が認められている**（利用規約 https://spire-codex.com/terms ）
   - 「公開APIとウィジェットは無料で使える（商用も可）」と書かれています
   - 禁止されているのは「公開API**以外**のページを自動で取る・丸ごと複製する」こと。**APIだけを使えば問題ありません**
   - 回数制限：登録なしで **1つのAPIにつき1分15回**（`/api/rate-limits` で確認）。
     カード一覧は1回の呼び出しで全577枚が取れるので、十分に足ります
   - 名前・効果テキスト・画像の権利は Mega Crit にあります。個人ツールの中で参考に使うのは問題ありませんが、配布はしません
2. **日本語名がゲーム公式のものと同じ**
   - `?lang=jpn` を付けると、名前・効果・種類・レアリティが日本語で返ってきます
   - 画面から読み取った日本語名でそのまま検索できます（CLAUDE.md の「公式の日本語名と完全に一致させる」を満たせます）
3. **CLAUDE.md で欲しいデータがほぼそろっている**
   - カード：名前（英語・日本語）、コスト、レアリティ、種類、効果、キャラ（`color`）、ダメージやブロックの数値、強化後
   - 性能：ピック率、勝率、取った場合の勝率の差（`lift`）、信頼区間、キャラ別、アセンション区分別、パッチ別
   - レリック・ポーション・アセンションのAPIもあります（ショップ判断に使えます）
4. **ラン履歴をまるごとダウンロードできる**（`/api/exports/runs`。全部で約271万件、約9.4GB。パッチ別のファイルに分かれている）
   - 大きいので、最初は使わずに集計済みの統計APIだけで始めるのがおすすめです

## 使う予定のAPI（Spire Codex）

| 用途 | API | 確認した中身 |
|---|---|---|
| カードの内容（日本語） | `GET /api/cards?lang=jpn` | 577枚。`id`, `name`, `cost`, `type`, `rarity`, `color`, `description`, `vars`, `upgrade` など |
| カードの内容（英語） | `GET /api/cards?lang=eng` | 同じ `id` で英語名と対応づけられる |
| カードの統計（区分別） | `GET /api/runs/metrics/cards?bracket=a10` | `win_rate`, `pick_rate`, `lift`, `offered`, `picked`, `pick_rate_by_act`, `tier` |
| カード1枚の詳しい統計 | `GET /api/runs/stats/cards/{id}` | 区分ごと・キャラごとの勝率 |
| レリック・ポーション | `GET /api/relics`, `GET /api/potions` | ショップ判断用 |
| 統計があるパッチ | `GET /api/runs/versions` | `stat_versions`：v0.107.0〜v0.111.0 |
| アセンション別の全体勝率 | `GET /api/runs/community-stats` | A0〜A10 それぞれのラン数と勝率 |

## 注意点
- 統計は、Spire Codex にランをアップロードした人のデータです（プレイヤー全員のデータではありません）。
  人数が多いのは A10（約70万ラン）と A0（約41万ラン）です
- `bracket`（アセンション区分）：API仕様書の説明を確認した結果、アセンションで絞れるのは **`a10`（A10だけ）のみ**。
  指定しなければ A0〜A10 全部になる。ほかに `solo`（ソロだけ）やパッチ（例：`v0.111.0`）を `:` でつないで組み合わせられる
  （例：`solo:a10:v0.111.0`）。A0〜A9 を「低・中」に分けたい場合は、ラン履歴のダウンロード（`/api/exports/runs`）から自分で集計する必要がある（2026-11-11 確認）
- 他のサイト（STS Tracker、STS2 STATS）は規約がはっきりしないため、自動取得はしません。
  必要になったら、手で見て比べる参考にとどめます
- CLAUDE.md のとおり、**最終的にはゲームファイルのデータを正とします**。Spire Codex のデータとは、あとで照合します

### Metabot.gg で取れるもの（実際に試した結果）
- カード1枚ごと（`lookup_game_entity`）：ティア、勝率、ピック率、キャラ、種類、レアリティ
  - 例：Barricade（バリケード）→ ティアB、勝率31.4%、ピック率1.6%
- キャラごとの上位カード一覧（`get_game_meta`）
- **アセンション別、パッチ別、件数（サンプル数）は取れない**
- カード名の検索は英語名で行う（日本語名では見つからなかった）。英語名は Spire Codex の対応表から引けます
- ピック率の数え方が Spire Codex と違う（Spire Codex は「提示されたときに取った割合」でバリケードは35.5%。Metabot は値がずっと小さく、全体に占める割合と思われる）。**数字をそのまま混ぜて平均すると、かえって不正確になります**

## 複数データの組み合わせ方（案）
1. **Spire Codex を主なデータにする**：件数、信頼区間、アセンション別、パッチ別がそろっているため
2. **Metabot を「別の意見」として使う**：生の数字は混ぜず、**キャラ内での順位（何位くらいか）** に直して比べる
   - 2つの順位が近い → 評価の信頼度を上げる
   - 2つの順位が大きく違う → 「評価が割れている」と一言コメントで伝える
3. 自分のプレイデータが増えたら、F-15 の計画どおり自分のデータの比重を上げる
4. 表示ウィンドウには「出典：Spire Codex / MetaBot.GG（リンク付き）」を表示する（Metabot の条件）
